# Project Architecture

## Application

`src/BlazeMd2Pdf` is a .NET 10 Blazor WebAssembly application designed to run as a static client application, including GitHub Pages. MudBlazor 9.9.0 supplies the UI and MudBlazor.Markdown 9.0.0 renders Markdown in the browser.

The application keeps document rendering and Markdown export client-side. There is no server-side dependency in the current architecture.

## Conversion and rendering pipeline

The application uses two complementary paths:

### PDF to Markdown

`Services/Abstract/IConverterService.cs` defines the document-reading conversion contract and `Services/Concrete/ConverterService.cs` implements PDF text extraction. PDF files uploaded by the browser are copied asynchronously into memory before PdfPig opens them because PdfPig's parser is synchronous.

### Markdown to PDF, HTML, PNG and JPEG

Markdown export is intentionally browser-based rather than generated by manually positioning PDF text. The pipeline is:

```text
Markdown source
      |
      v
MudBlazor.Markdown
      |
      v
Rendered browser DOM + CSS
      |
      +------> HTML
      |
      +------> PNG / JPEG via html2canvas
      |
      +------> PDF via html2pdf.js
```

`Controls/MarkdownExportSurface.razor` owns the rendered Markdown DOM used by all export formats. `Services/Abstract/IMarkdownExportService.cs` and `Services/Concrete/MarkdownExportService.cs` provide the .NET abstraction over the browser export JavaScript.

The PDF and image exports therefore use the browser's normal CSS layout and line wrapping. This avoids the narrow-column and text-measurement problems associated with hand-built PDF layout engines.

The current PDF implementation uses `html2pdf.js` in the browser. It is suitable for the static GitHub Pages goal, but it is not equivalent to a Chromium `page.pdf()` pipeline: it is a client-side HTML/canvas-based export. Exact Chromium rendering would require a server-side browser renderer and would therefore be a separate architecture option.

## Pages

Markdown export is exposed through dedicated pages:

- `/topdf` exports Markdown to PDF.
- `/tohtml` exports Markdown to HTML.
- `/topng` exports Markdown to PNG.
- `/tojpeg` exports Markdown to JPEG.
- `/tomarkdown` imports PDF files and converts their extracted text to Markdown.

`Pages/MarkdownExportPage.razor` contains the shared upload, preview, presentation options, and export controls used by the format-specific pages.

## Controls and presentation

- `Controls/MarkdownExportSurface.razor` renders the Markdown document that is exported.
- `Controls/MarkdownViewer.razor` provides Markdown preview functionality used by the import workflow.
- `Controls/PdfViewer.razor` provides PDF viewing functionality where applicable.
- `wwwroot/css/markdown-export.css` contains the shared document and print/export presentation rules.
- `wwwroot/js/download.js` contains browser download helpers and the HTML/PDF/PNG/JPEG export bridge.

The export options include page format and orientation, page margins, font family, font size, line height, alignment, image quality, and rasterization scale. The document width is calculated from the selected A4 orientation and horizontal margins so the preview matches the intended page geometry.

## Fonts

The export surface uses CSS font families available to the browser. The application does not need to embed proprietary Microsoft font files to perform Markdown export. Font availability therefore follows the browser and the CSS font stack configured by the user.

## Dependencies

The relevant rendering/export dependencies are ASP.NET Core Blazor WebAssembly 10.0.11, MudBlazor 9.9.0, MudBlazor FontIcons MaterialSymbols 1.5.0, MudBlazor.Markdown 9.0.0, AngleSharp 1.7.2, and PdfPig 0.1.16. `html2pdf.js` and its browser-side dependencies are loaded by `wwwroot/index.html` for client-side PDF/image export.

The previous direct `MarkItDown` package is not part of the Markdown export pipeline. A document-to-Markdown engine such as ManagedCode.MarkItDown may be introduced later for additional input formats, but it is not required for the current browser-only Markdown export goal.

## Static hosting

The application is intended to remain deployable as a static Blazor WebAssembly site. GitHub Pages hosts the application assets, while conversion and export work takes place in the user's browser. Future integrations such as an MCP connection must therefore be optional and must not make the static application dependent on a backend service.
